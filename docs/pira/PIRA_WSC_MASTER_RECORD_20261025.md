# 国連協提案・Webセキュリティ診断｜統括記録

記録日：2026-10-25。これは会話上の確定事項・実測・検討事項のスナップショットであり、GitHubへの反映を意味しない。

## 1. 最重要決定

- 国連協向け施策は、組合自身と所属企業に同じ**URL型の公開Webセキュリティ簡易診断**を提供する案を優先検討。国連協・組合との正式合意は未了。
- K氏が必要とするのは**企業名・本店所在地・WebサイトURL**。企業を識別して国連協として調査し、共同購買・組合支援施策を企画するため。企業への直接営業は今回の主目的ではない。
- 従来の「組合にアンケート診断→所属企業へアンケート案内」では組合の協力が障壁。組合にまず価値あるURL診断を提供し、所属企業にも同じ成果を還元する仕組みにより、企業基本情報を共有する合理性を作る。情報提供を診断の見返りとして強制しない。
- WSCは**atLIB社内専用**。Windows PowerShell 5.1、ローカルCSV→公開情報取得→JSON→固定判定・固定解説→HTML/結果CSV。外部公開、DB、GCP、SaaS化、課金、CRM、AI API、営業導線は今回不要。既存資産は有用な範囲で再利用するが、将来のサービス化に備えた先行開発はしない。
- CSVは**`企業名,本店所在地,URL`の3列**。企業名と本店所在地は識別・表示用、診断判定はURL起点の公開情報のみ。組合別にはCSVを分ける案。組合ID列は追加しない。
- 約10,000社を低工数・低コストで診断する目標。現時点で一括運用・費用・所要時間は実証していない。
- PIRAの**アンケート診断システム構築のみ**、WSCの成立・完成確認後に一旦STOPする方針。現時点で停止済みとは扱わない。既存仕様・PR #16・Decision Logは保存。
- **Secure Guardは約350台の顧客展開のため継続**。**共同顧客ポータルは将来のサービス展開に向けて並行継続**。PIRA共同購買システムも今回の停止対象ではない。
- このスレッドが設計・統括・承認、Work/VS Codeが実装・テスト・PR担当。独自の事業判断・判定文言作成は不可。仕様不足はSTOP。

## 2. 技術実測（atLIB v2 JSON）

対象 `https://www.atlib.jp/`、メール照会ドメイン `atlib.jp`、日時 `2026-10-25T15:21:34.0728129+09:00`。

| 項目 | 取得値 | 解釈上の制限 |
|---|---|---|
| HTTP GET | 200 | 1応答のみ、リダイレクト追跡なし |
| TLS | Tls13、VALIDATED、policyErrors=None | 旧TLS方式の無効化は未検証 |
| 証明書 | CN=www.atlib.jp、Let's Encrypt YE1、期限2027-01-21、残87日 | 取得時点の結果 |
| HSTS | max-age=31536000; includeSubDomains | 存在・設定値の確認 |
| CSP | HTTPヘッダー null | HTML内・他ページは未調査 |
| X-Frame-Options | HTTPヘッダー null | CSP frame-ancestors等の別設定は未確認 |
| X-Content-Type-Options | nosniff | 存在の確認 |
| Referrer-Policy | strict-origin-when-cross-origin | 存在の確認 |
| Permissions-Policy | camera=(), microphone=(), geolocation=() | 存在の確認 |
| SPF | v=spf1 include:_spf.google.com include:spf.bmv.jp ~all | SPF DNS参照上限・完全構文検証は未実施 |
| DMARC | v=DMARC1; p=none | 監視中心、受信側に隔離・拒否を要求しない |

| DS | NO_RECORD | DNSSEC署名検証ではない |

## 3. 診断・判定の確定思想

- Read-onlyの軽量な公開Web/TLS/DNS確認。侵入試験、ポートスキャン、攻撃テスト、ログイン領域探索は行わない。
- **取得値だけを根拠に、同一JSON・同一ルール版・同一文章版で同一結果**。推測による補完、AIによる実行時文章生成は禁止。
- 利用者向け表示区分は**「設定確認済み」「追加確認推奨」**。安全性点数、レーダーチャート、危険度ランキング、良い/悪いの採点は行わない。
- **危険性を隠さないが危険度を採点しない**。HTTPS未対応など確認済みの重要な状態は優先的な確認を促す。CSP等はサイト構成依存のため脆弱性と断定しない。
- 通信失敗・判定不能は内部証跡に保持し、利用者向けには原則表示しない。**設定不存在と取得失敗は別**。未確認を「安全」扱いしない。
- 「追加確認推奨」は**atLIBの追加調査の約束ではない**。企業の管理担当者・保守会社へ確認するための案内。無料一次診断で完結。
- MXは独立した利用者向けセキュリティ解説にしない。DNSSECはDS照会だけでは評価不能のため利用者向けから除外。
- 実測根拠は対象URL、取得値、設定の意味を提示。技術的根拠は事前に検証したRFC・標準・公的解説の出典名/URL/該当箇所。出典未確認なら創作しない。

## 4. レポート確定仕様

- 対象読者はITに不案内な経営者・組合担当者。
- 各診断項目は**①今回の診断結果 ②そう判断した根拠（実測値と平易な説明） ③なぜ大切なのか（業務に即した例・技術出典） ④次に確認すること（管理担当者への具体的な質問）**。
- 「取得できませんでした」「確認できませんでした」など調査側の都合を主語にしない。ただし根拠欄では正確な取得状態を明記する。
- 表紙→**承認済み固定「はじめに」**→概要FV→Web詳細→メール詳細→今後の確認事項→技術根拠・出典。
- 概要FVは**Webとメールの2領域カード＋確認事項フォーカス**。固定的な7項目表示ではなく入力に応じて動的に変わる。デザイン・文章の微調整は実物確認後。
- 末尾に「公開Web・メール設定の確認であり、企業全体のセキュリティや安全性を評価するものではない」趣旨の短い注記。

### 4.1 承認済み「はじめに」全文（表紙直後・全企業共通・無断改稿不可）

# WebサイトのURLだけで、ここまで分かることをご存じですか？

会社のWebサイトのURLは、誰でも見ることができる情報です。

実は、このURLを手がかりに、インターネット上に公開されているさまざまな設定情報を調べることができます。

例えば、次のようなことです。

**Webサイトの通信が暗号化されているか**

お客様がWebサイトを閲覧する際の通信を守る仕組みについて、外部から確認できます。

**Webサイトにどのような保護設定があるか**

不正なプログラムの動作や、他サイトによる画面の悪用を抑えるための公開設定を確認できます。

**会社を装った偽メールへの対策**

対象ドメインに公開されているメール認証の設定から、なりすまし対策の方針を確認できます。

**特別な社内情報を調べているわけではありません**

今回の診断では、社内のパソコンや業務システムにログインしたり、機密情報を取得したりすることはありません。

インターネット上に公開されている情報を確認し、その意味を分かりやすく整理しています。

**大切なのは、結果を知ることから**

設定があるから絶対に安全、設定が見当たらないから危険、という単純なものではありません。

まずは、自社のWebサイトやメールにどのような仕組みが使われているのかを知り、必要に応じて管理担当者や保守会社へ確認することが大切です。

**このレポートが、自社のセキュリティについて考えるきっかけになれば幸いです。**
