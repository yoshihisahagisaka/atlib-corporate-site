# WSC Phase 2C Fit / Gap（2026-10-26）

## 方式比較と採用

| 方式 | DNS/IP拘束 | Windows保守性 | 採用 |
|---|---|---|---|
| Node.js HTTPS/TLS/DNS | `tls.connect`で検証済みIPへ明示接続可能 | Node 20+で実行可能 | 採用（ただし外部実行は無効） |
| PowerShell v2の直接利用 | atLIB固定・ソケットIP拘束なし | 原本を改変できない | 不採用 |
| Phase 2B契約アダプター | 取得結果の検証契約を再利用 | 既存の隔離テストと整合 | 採用 |

`restricted-network-probe.mjs` は、コード内固定文字列ではなく、外部から注入する非ログ出力の承認ストアを使う。承認レコードは承認ID、対象URL、失効時刻、残実行回数（1回）、有効状態を厳密に結び、DNS解決より前に原子的に消費する。対象URL不一致、失効、使用済み、または承認不在では停止する。承認ID・承認内容はログに出力しない。

承認の発行、保管、失効は今回未実装である。将来の承認済み運用では、ソースコード・環境変数の平文・実行ログから分離した秘密管理基盤に一回限りの能力レコードを保管し、発行者、対象URL、期限、取消、消費監査を統括管理する必要がある。今回のテストは承認境界と注入契約のみを通過し、実接続は一切実行していない。

## 実装契約

承認時だけ、Node標準DNSで解決した公開IPをPhase 2Aポリシーで検証し、TLS接続先をそのIPに固定する。SNI・Hostは元ホスト名、証明書検証は有効、リダイレクト追跡はなし、応答上限・AbortSignal・タイムアウトを適用する。TLSの`secureConnect`時点で`remoteAddress`、証明書検証状態、プロトコル、証明書情報を保持し、応答終了後のソケット参照には依存しない。固定IP不一致または証明書検証失敗は取得を中止する。

明示メールドメインだけをTXT照会し、SPF・DMARCをJSON 2.0形状で返す。`FOUND` は該当形式のレコードが取得できた状態、`NO_RECORD` は照会成功かつTXT値がなく該当レコードがない状態、`UNVERIFIED` はメールドメイン未指定、DNS取得失敗、または形式不正である。TXT値があるのにSPF/DMARC形式として認識できない場合は `RECORD_FORMAT_INVALID` を補足に残し、`NO_RECORD` にしない。これによりVS1の `DMARC_ABSENT` は形式不正・未確認・取得失敗から生成されない。メールドメイン未指定は推測せず未確認とする。

Web接続前のDNS解決と、SPF/DMARCの各TXT照会には個別の時間上限を適用する。時間切れは `DNS_ACQUISITION_TIMEOUT`、中断要求は `DNS_ACQUISITION_ABORTED` として取得失敗に記録し、`NO_RECORD` と混同しない。タイマーと中断リスナーは結果確定時に解放し、時間切れ後に返った結果は採用しない。

Node.js標準の`node:dns/promises`はこの呼び出し経路で問い合わせ自体を確実に取消す契約を提供しない。そのため時間切れ・中断時には呼出側の待機と結果採用を停止する一方、基盤側のDNS問い合わせが短時間残る可能性がある。この制約は実運用の外部DNS接続前に、リゾルバー・監視・同時実行数の運用設計と合わせて統括確認が必要である。

## 隔離テストとSTOP

`restricted-network-probe.mjs` 自体は、DNS・承認ストア・ネットワーク交換をテスト専用の依存関係に差し替えて検証する。承認なし、対象URL不一致、失効、使用済みがDNS前に拒否されること、検証済みIP・SNI・Host・TLS検証要求が交換契約に渡ること、DNS分類、形式不正、接続前DNSとTXT DNSの時間切れ、遅延応答の不採用、中断要求を確認する。形式不正のDMARCからVS1判定JSONとHTMLを生成し、`DMARC_ABSENT` が出ないことも確認する。Phase 2B/2A/VS1回帰を併用する。実サイトへの接続、承認情報の発行、実DNS／TLS、GCP、Productionは未実施。

実サイト試験には、対象URL一覧・所有または調査許可・頻度上限・実行時間帯・承認トークンの保管方法を統括承認すること。DNS再解決後の固定IPと実ソケット接続先を運用環境で照合できない場合はSTOPする。
