# WSC Phase 2D｜PIRA限定実測・実行前環境（2026-10-27）

## 1. 目的と境界

PIRA公式サイト候補 `https://pira.or.jp/` の将来の限定実測に備え、Phase 2Cの承認ストア注入契約をローカル限定で実装した。今回の承認レコードはSyntheticテスト専用であり、PIRAまたは実サイト向けの承認情報は発行していない。外部DNS、TLS、HTTPSは呼び出さない。

## 2. 実装

`tools/wsc-phase2d/approval-store.mjs` はアクセス制限されたローカル領域に、承認レコードを保存する。承認は次を拘束する。

- 完全一致するHTTPS URL（`www`、末尾スラッシュ、パス、クエリを含む）
- 実行者
- 有効期限
- 一回限りの消費

消費は、承認ファイルを原子的に `grants` から `claimed`、次に `consumed` へ移動する。別の消費者は元の承認を取得できない。取消は未消費の承認を `revoked` に移動する。監査ログと実行ログには承認値を出さず、SHA-256の参照値だけを記録する。

`tools/wsc-phase2d/preflight-environment.mjs` は、承認領域、実行ログ、Phase 2Aのローカル隔離成果物ストアを同じローカルルートに準備する。外部通信モジュールを読み込まない。

## 3. 将来の承認後の実行手順

1. 権限者が `https://pira.or.jp/` を含む完全な実測対象URL、実施者、時間帯、範囲を承認する。
2. 秘密管理されたローカル承認ストアへ、期限付き・一回限り・実行者拘束の承認を発行する。値をCLI履歴、ログ、HTML、JSONへ出力しない。
3. 実行前に、承認のURL一致・期限・未使用・取消状態を確認する。
4. Phase 2Cの`createRestrictedNetworkProbe`へ承認ストアと承認IDを注入する。承認がない場合、DNS前に停止する。
5. 実測する場合も、HTTPS GET 1回、DNS最大4回（メールドメイン未指定ならWeb照合のみ）、同時実行1、HTTPS 15秒、DNS各5秒、1 MiB、リダイレクト自動追跡なし、再試行なしを守る。
6. メールドメインは未指定のまま `null` とし、SPF/DMARCをURLから推測しない。
7. JSON 2.0、判定JSON、HTML、整合性情報をPhase 2Aの隔離ストアへ保存し、SHA-256を検証する。PDFが必要な場合はローカルHTMLからブラウザの印刷ダイアログを使用する。

## 4. Synthetic検証

次を外部通信なしで確認した。

- 承認なし、URL不一致、期限切れ、使用済み、取消済みの拒否
- 同一承認への複数消費要求から成功が1件だけとなること
- 承認監査・実行ログに承認値を含めないこと
- Synthetic診断JSONからVS1の判定JSON・HTMLを生成すること
- `company.json`、`diagnosis.json`、`result.json`、`report.html`、`integrity.json` の隔離保存とSHA-256整合性確認

## 5. 未承認事項とSTOP条件

以下が統括承認されるまで実測を開始しない。

1. PIRAサイト管理主体と調査権限。
2. 実測対象の完全URL、実施日時、実施者、緊急停止窓口。
3. 実サイト向け承認の発行者、ローカル保管場所、OSアクセス権、取消・監査の運用。
4. 成果物の保存先、アクセス権、保持期間、削除責任者。
5. メールドメインを診断するか否か（未指定なら診断しない）。
6. DNSの開始済み問い合わせをNode.jsが確実に取消せない制約の受容。

上記に加え、実DNS/TLS/HTTPS、GCP・Production変更、外部配布、メール送信、mainマージは禁じる。
