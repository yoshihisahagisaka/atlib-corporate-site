# Secure Guard 商用管理基盤｜単一顧客ログイン・Organization Membership 決定記録

Date: 2026-10-22 JST
Status: **Business/Architecture Decision（ユーザー承認済み）**
Canonical context: Draft PR #44、PR #7/#9、2026-10-22 GCP無人解約E2Eチェックポイント。実装・実機操作はPHP脆弱性対応中につき停止。

## 最上位原則（確定）
1. **顧客用とatLIB用の別システム、別管理画面、別業務ロジック、別ジョブを開発しない。**
2. **顧客社員も顧客先常駐のatLIB社員も、同じSecure Guard顧客ログイン、同じUI/API/DB/ジョブ/監査を使う。**
3. 人の雇用主がatLIBか顧客かではなく、**当該顧客Organizationに対する個人のMembershipとRole**で操作可否を判定する。
4. atLIB常駐社員は「atLIB内部管理アカウントで代理操作」するのではない。**顧客Organizationの運用者アカウントとして操作する**。顧客社員も同じ方式で参加できる。
5. 個人アカウントを共有しない。本人の操作として監査し、顧客をまたぐアクセスは明示Membershipがある場合のみ許可。常駐契約・担当終了時はMembershipを失効。
6. 顧客ごとの境界は画面の絞り込みだけでなく、サーバー側認可、データ取得、ジョブ対象確定、監査まで強制する。
7. DNSFilter MSP親に対する仕入・請求精算等の特権操作が必要でも、顧客の日常運用に別ログイン/別システムを作る理由にはしない。特権操作の承認と実行権限は別途厳格化する。

## 既決の商用前提
- 初回顧客はWindows約350台、PoC後段階展開。既存のatLIB常駐運用チームが顧客側の運用者として対応する。
- 将来のPIRA顧客は同じ画面を顧客自身が操作する。顧客ごとに実装を複製しない。
- 月額基本5,000円/社＋実登録端末300円/台・月（運用費込み、税別）。今回350台はレベニューシェアなし。標準初期導入費300,000円を今回限定0円。実登録台数の締め定義、DNSFilter仕入数量との照合は未確定。
- 利用状況によるPolicy分離、悪性ドメイン遮断、社内外保護、端末単位可視化、運用・遮断解除、PoC段階導入の6項目を提案訴求として承認。
- FortiGate競合は顧客提案には載せず、PoCの内部技術確認事項。競合で実効保護が確認できなければ展開前に解消する。
- 管理画面は早期実装するが、初回導入時はDNSFilter管理画面による暫定運用を許容（別システムを開発しない）。
- GCP/DNSFilter実機操作、Secret/IAM変更、デプロイ、Work実装指示はPHP脆弱性対応が落ち着くまで停止。設計とGit/docs記録のみ。

## 次の詳細設計（提案。実装承認ではない）
### 論理モデル
- Identity/User：一人の利用者を一意識別。個人認証・停止状態。
- Customer Organization：顧客の利用・データ境界。DNSFilter Organizationとの対応は別の外部IDマッピングで保持。
- Membership：user_id、customer_org_id、role、status、招待・承認・失効日時、権限付与者。ユーザーは複数Organizationに所属可能。
- Roles（候補）：org_admin、operator、viewer。申請者・承認者の職務分離を操作別に適用。
- Operation/Audit：actor_user_id、customer_org_id、membership_id、action、approval_id、対象、時刻、結果。代理/なりすましのフラグで区別する設計を基本にしない（顧客運用者として本人が操作）。
- Customer portalと運用ジョブは同じAPI契約と認可判定を利用。高権限のDNSFilter APIキーをブラウザへ露出しない。

### 初期権限マトリクス案（次工程で承認）
| 操作 | org_admin | operator | viewer |
|---|---|---|---|
| 自社端末・Site・登録数・保護状態の閲覧 | 可 | 可 | 可 |
| 自社端末登録/削除要求 | 可 | 可 | 不可 |
| 遮断解除申請 | 可 | 可 | 不可 |
| Policy例外の承認・実適用 | 高リスク承認ルールに従う | 申請まで | 不可 |
| Membership招待・失効 | 可（権限上限あり） | 不可 | 不可 |
| 契約/請求数量閲覧 | 可 | 要設定 | 要設定 |
| 解約申請 | 可 | 要承認 | 不可 |
| Organization DELETE | 直接実行不可。別途承認済みJobのみ | 不可 | 不可 |

### 必須テスト
- 同一Organizationで顧客社員とatLIB常駐社員が同一画面/同一APIを利用する。
- 異なるOrganizationへの閲覧・操作・ジョブ投入を403等で拒否する。
- 複数Organization所属者の切替で権限が漏れない。
- Membership失効後のアクセスと進行中操作を停止する。
- UI制限だけでなくAPI直接呼出し、ジョブ、監査までテナント境界を検証する。
- 高リスク操作の承認・実行を分離し、本人・対象・時刻・結果を記録する。
